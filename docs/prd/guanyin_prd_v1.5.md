## 1. 产品概述

观音灵签是问心运势测算网站的核心功能之一，为用户提供完整的抽签、解签体验。用户通过登录验证后进入观音灵签页面，输入求问问题，选择鼠标控制或手势控制方式进行抽签，获得100签中的随机一支签文后，由 AI（Kimi API）结合用户的具体问题提供个性化解读，并支持多轮对话追问。所有抽签记录自动保存到数据库，便于后续查看和管理。

### 设计理念

- **沉浸式体验**：全屏 Three.js 粒子特效背景，配合复古噪点滤镜，营造神秘、庄重的氛围感
- **双模式交互**：支持手势控制（MediaPipe Hands）和鼠标控制两种方式，满足不同场景需求
- **AI 个性化解读**：结合固定签文底本和用户具体问题，提供针对性、个性化的解读内容
- **仪式感设计**：从进入页面、输入问题、选择模式、抽签动画、结果展示的完整流程，注重用户心理体验
- **数据持久化**：完整的抽签记录、对话历史自动保存到数据库

## 4. 用户流程

### 4.1 完整流程

```
用户访问首页
    ↓
点击观音灵签入口
    ↓
【验证】未登录 → 弹出登录框 → 登录成功
    ↓
进入观音灵签页面
    ↓
【状态1】页面初始化
    - 自动启动摄像头（手势识别）
    - 显示全屏粒子背景
    - 显示噪点滤镜
    - 显示问题输入框和两个控制按钮
    ↓
用户输入求问问题
    ↓
【状态2】输入完成
    - 选择"手势控制"或"鼠标控制"
    ↓
【状态3】选择模式后
    - 输入框和按钮淡出消失
    - 进入抽签状态
    ↓
【状态4】抽签中
    - 粒子系统进入抽签模式
    - 手势控制：左右挥手触发抽签
    - 鼠标控制：长按签筒触发抽签
    - 2秒抽签动画
    ↓
【状态5】出签结果
    - 粒子颜色随签文等级变化
    - 显示签文卡片
    - 异步保存抽签记录到数据库
    - 显示 AI 聊天区域
    - AI 开始初次解读
    ↓
【状态6】对话中
    - AI 解读显示
    - 用户可输入追问问题
    - 支持多轮对话
    - 对话历史自动更新保存
    ↓
【可选操作】
    - 点击"查看签文"/"隐藏签文"
    - 点击"AI 解读"/"隐藏解读"
    - 点击"重新抽签" → 重置状态，回到初始
    - 点击"返回首页" → 离开页面
```

## 5. 页面状态流转

### 5.1 页面状态定义

| 状态 | 说明 |
|------|------|
| `IDLE` | 初始状态，未选择模式，粒子响应手势但不抽签 |
| `INPUT_FOCUSED` | 聚焦输入框，粒子固定模式 |
| `GESTURE_MODE` | 选择手势控制模式 |
| `MOUSE_MODE` | 选择鼠标控制模式 |
| `DRAWING` | 抽签动画中 |
| `RESULT` | 显示结果和 AI 解读 |

### 5.2 状态流转图

```
IDLE ←→ INPUT_FOCUSED
  ↓
GESTURE_MODE / MOUSE_MODE
  ↓
DRAWING
  ↓
RESULT → (点击"重新抽签") → IDLE
```

## 6. 功能详细说明

### 6.1 前置验证

**功能说明**：用户必须登录才能使用观音灵签功能。

**实现逻辑**：
- 用户在首页点击观音灵签入口时，检查登录状态
- 未登录则弹出登录框
- 登录成功后自动进入观音灵签页面
- 进入页面后，传递 `userId` 给业务逻辑，用于数据保存

### 6.2 页面体验

#### 6.2.1 全屏粒子特效

**功能说明**：Three.js 粒子系统提供沉浸式背景。

**功能点**：
- 背景粒子系统（数千个粒子）
- 粒子签筒（特定形状排列）
- 粒子签条（多根签条）
- 粒子颜色随签文等级变化（吉签金色系等）

**状态响应**：
- `IDLE/INPUT_FOCUSED`：粒子响应手势（散开/移动/聚合）
- `GESTURE_MODE/MOUSE_MODE`：粒子进入等待抽签模式
- `DRAWING`：粒子抽签动画（签筒晃动、签子飞出）
- `RESULT`：粒子颜色根据签文等级变化

#### 6.2.2 复古噪点滤镜

**功能说明**：CCD 复古噪点滤镜，营造神秘感。

**实现方式**：全屏 Canvas 覆盖层，动态生成噪点效果。

### 6.3 问题输入

#### 6.3.1 问题输入框

**功能说明**：用户输入求问的具体问题。

**UI 位置**：页面中下底部，不遮挡主视觉。

**交互说明**：
- 点击输入框聚焦，页面状态变为 `INPUT_FOCUSED`
- 输入框失焦，页面状态回到 `IDLE`

#### 6.3.2 输入框高亮提示

**功能说明**：用户未输入问题就点击控制模式时，高亮提示输入。

**实现逻辑**：
- 点击"手势控制"或"鼠标控制"时检查问题是否为空
- 为空则高亮输入框 2 秒
- 不触发模式选择

### 6.4 控制模式

#### 6.4.1 手势控制模式

**功能说明**：通过 MediaPipe Hands 识别用户手势，挥手触发抽签。

**实现逻辑**：
- 页面加载时自动启动摄像头
- 识别"左右挥手"手势
- 手势模式下，挥手触发抽签流程

#### 6.4.2 鼠标控制模式

**功能说明**：通过鼠标长按签筒触发抽签（摄像头不可用时的备选方案）。

**实现逻辑**：
- 鼠标长按签筒区域
- 签筒晃动动画
- 松开鼠标触发抽签流程

### 6.5 抽签流程

**功能说明**：2 秒抽签动画，营造仪式感。

**动画内容**：
- 粒子签筒晃动
- 粒子签条旋转
- 签子飞出动画
- 动画时长：2 秒

### 6.6 结果展示

#### 6.6.1 签文卡片

**功能说明**：展示完整签文信息。

**展示内容**：
- 签编号（1-100）
- 签等级（上上签、上签、中签、下签、下下签）
- 签标题
- 签诗
- 典故
- 释义

**交互功能**：
- 支持"查看签文"/"隐藏签文"切换
- 卡片支持关闭

#### 6.6.2 AI 聊天区域

**功能说明**：右侧边栏显示 AI 解读和对话。

**UI 位置**：页面右侧，可独立显隐。

**交互功能**：
- 支持"AI 解读"/"隐藏解读"切换
- 支持输入追问问题
- 支持多轮对话

### 6.7 AI 解读

#### 6.7.1 初次解读

**功能说明**：抽签后，AI 结合签文和用户问题进行初次解读。

**调用时机**：出签后自动触发。

**提示词规则**：
- 签文底本锁死：不修改、编造、删减签文内容
- 个性化解读：完全匹配用户具体问题，不使用通用套话
- 知识库边界：仅使用内置 100 签知识库
- 输出格式：使用中文标点，禁止出现英文
- 字数灵活：问题简单精简，问题复杂深入，不超过 400 字
- 初次解读：引用签诗，结合问题解读，解释典故，给出建议
- 追问规则：不重复引用签诗，直接围绕核心含义回复

#### 6.7.2 多轮追问

**功能说明**：用户可以继续提问，深入了解签文启示。

**对话历史**：
- 保留完整对话历史
- 后续回复结合上下文

### 6.8 数据保存

#### 6.8.1 抽签记录自动保存

**功能说明**：出签后，异步保存抽签记录到数据库，不阻塞用户体验。

**保存时机**：出签后立即调用。

**保存内容**：
- `id`：自动生成 UUID
- `user_id`：当前登录用户 ID
- `type`："guanyin"
- `question`：用户问题
- `result`：签文数据（JSONB）
- `conversation`：对话历史（JSONB，初始为空）
- `created_at`：创建时间
- `updated_at`：更新时间

#### 6.8.2 对话历史增量更新

**功能说明**：每次 AI 回复后，更新对话历史到数据库。

**更新时机**：每次 AI 回复后调用。

**更新内容**：
- `conversation`：完整对话历史
- `updated_at`：更新时间

### 6.9 其他功能

#### 6.9.1 重新抽签

**功能说明**：重置状态，回到初始页面，可以重新抽签。

**重置内容**：
- 页面状态回到 `IDLE`
- 清空问题
- 清空选中签文
- 清空对话历史
- 清空错误信息
- 清空记录 ID

#### 6.9.2 返回首页

**功能说明**：离开观音灵签页面，返回首页。

**清理内容**：
- 停止摄像头
- 清理页面状态

## 7. 数据结构

### 7.1 签文数据（100 签）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | number | 签编号，1-100 |
| `level` | string | 签等级：上上签、上签、中签、下签、下下签 |
| `title` | string | 签文标题 |
| `poem` | string | 签诗 |
| `story` | string | 典故 |
| `meaning` | string | 含义解释 |

### 7.2 对话消息

| 字段 | 类型 | 说明 |
|------|------|------|
| `role` | string | 角色："user"（用户）或"assistant"（AI） |
| `content` | string | 消息内容 |

### 7.3 测算记录（数据库）

**表名**：`divination_records`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 记录 ID，主键，自动生成 |
| `user_id` | UUID | 用户 ID |
| `type` | VARCHAR | 测算类型："guanyin" |
| `question` | TEXT | 用户问题（可空） |
| `result` | JSONB | 签文数据 |
| `conversation` | JSONB | 对话历史（可空） |
| `created_at` | TIMESTAMPTZ | 创建时间，默认当前时间 |
| `updated_at` | TIMESTAMPTZ | 更新时间 |

## 8. 非功能需求

### 8.1 性能需求

| 指标 | 要求 |
|------|------|
| 页面加载 | 首次加载 ≤ 3 秒 |
| 抽签响应 | 手势/鼠标触发后 ≤ 2 秒动画 |
| AI 初次解读 | ≤ 10 秒（网络依赖） |
| AI 追问回复 | ≤ 8 秒（网络依赖） |
| 数据保存 | 异步不阻塞，用户无感知 |

### 8.2 兼容性需求

| 项 | 要求 |
|----|------|
| 浏览器 | 支持主流现代浏览器（Chrome、Firefox、Safari、Edge） |
| 手势控制 | 需要摄像头支持 |
| 鼠标控制 | 无特殊要求，备用方案 |

### 8.3 安全性需求

| 项 | 要求 |
|----|------|
| 登录验证 | 必须登录才能使用观音灵签 |
| API 鉴权 | 后端 API 验证用户身份 |
| 数据隔离 | 用户只能看到自己的记录 |
| 敏感信息 | API Key 等敏感信息不提交到 Git |
