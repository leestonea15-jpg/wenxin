## 概述

本次迭代包含三个独立子项目，按顺序实施：

- 点击卡片时判断登录状态

### 2.1 数据模型

#### Auth State（zustand store）
```typescript
interface User {
  id: string
  phone: string
  nickname?: string
  avatar?: string
  createdAt: string
}

interface AuthStore {
  user: User | null
  isLoading: boolean
  login: (phone: string, code: string) => Promise<void>
  logout: () => void
  sendCode: (phone: string) => Promise<void>
}
```

### 2.2 登录流程

#### 弹窗触发
```
用户点击"选择模式"卡片
    ↓
判断是否登录？
    ↓ 未登录
显示登录弹窗
    ↓
用户输入手机号 → 点击"获取验证码"
    ↓
输入验证码 → 点击"登录"
    ↓
验证成功
    ↓
判断是否新用户？
    ├─ 是 → 自动创建账号 → 登录成功
    └─ 否 → 直接登录成功
    ↓
关闭弹窗 → 进入对应页面
```

### 3.2 样式调整

- **文字白色**：确保可见性

### 3.3 手势识别状态管理

#### 状态定义
```typescript
type GestureState = 'waiting' | 'detecting' | 'success' | 'failed'
```

#### 状态流转
```
waiting (等待手势)
    ↓
detecting (识别中)
    ↓
success (识别成功) → 播放动画 → 进入结果页
    ↓ (10秒超时)
failed (识别失败) → 显示重试提示 + 直接开始按钮
```

#### 状态反馈内容

| 状态 | 中央道具 | 底部提示 | 其他 |
|------|---------|---------|------|
| waiting | 静态大图标 | "请做「摇铜钱」手势：..." | 左下角手势示意图 |
| detecting | 微动画 + ⏳加载 | "🎯 识别中..." | 道具轻微晃动 |
| success | 大动画 + ✨ | "✅ 识别成功！" | 绿色高亮，1.5秒后跳转 |
| failed | 静态图标 | "⚠️ 未检测到手势，请再试一次，或点击跳过" | 显示"直接开始"按钮 |

### 3.4 手势识别问题修复

#### 问题分析
- 手势检测可能过于严格
- 摄像头启动后没有立即开始检测
- 状态切换逻辑可能有问题
- 缺少清晰的状态反馈

#### 修复方案
1. **降低检测阈值**：
   - shake手势：deltaY 从 0.08 降至 0.05
   - shakeCount 从 3 次降至 2 次
   - throw_up手势：deltaY 从 0.2 降至 0.15

2. **摄像头就绪后自动开始检测**：
   - 在 `cameraReady` 变为 true 时自动调用 `startDetection()`

3. **添加超时机制**：
   - waiting状态超过10秒自动转为failed
   - 给用户明确的失败反馈和跳过选项

4. **添加调试日志**（开发时）：
   - 输出手势检测过程
   - 便于排查问题

### 3.5 GestureCamera 组件重写
- 移除 aspect-video 限制，改为全屏
- 调整所有元素的位置和尺寸
- 中央道具使用更大的尺寸（150-200px）
- 底部提示框使用更低调的样式（半透明白/灰色）
- 支持4种状态：waiting/detecting/success/failed
