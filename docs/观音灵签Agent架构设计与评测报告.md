## 二、核心设计方法与模块（11个模块）

### 1. ReAct (Reasoning + Acting) 框架

**位置：** `_react_loop()` (guanyin_harness.py:186-371)

**工作流程：**
```
观察(Observe) → 思考(Think) → 行动(Act) → 观察(Observe) → ... → 最终答案
```

**关键设计：**
- 最大3步循环限制，防止无限循环
- 工具调用解析器 `_parse_react_response()`
- 草稿本(scratchpad)记录思考过程
- 可配置的最大步数

**解决的问题：**
- ✅ 解决LLM"一步到位"的不准确性
- ✅ 支持多步推理和工具使用
- ✅ 透明化思考过程，便于调试

---

### 2. 分层记忆系统（3层架构）

**位置：** `GuanyinAgentMemory` (memory_system.py:136-526)

**层次设计：**

| 层级 | 类名 | 特点 | 持久化 |
|------|------|------|--------|
| L1 | `WorkingMemory` | 当前会话，deque存储，最大10轮 | ❌ |
| L2 | `ShortTermMemory` | 最近7天，标签检索 | ✅ 数据库 |
| L3 | `LongTermMemory` | 历史所有，AI摘要 | ✅ 数据库 |

**记忆检索策略：** `retrieve()` (memory_system.py:251-302)
```python
# 混合权重评分
score = (标签匹配 × 2) × 时间衰减 + 关键词匹配
```

**设计亮点：**
- **话题标签自动提取** - `extract_topic_tags()` 识别工作/感情/学业/财运/健康
- **按需加载** - 不预加载，检测到关键词(如"上次"、"之前")才检索
- **异步保存** - `asyncio.create_task()` 后台保存不阻塞主线程
- **权限控制** - 集成权限检查，防止越权访问

**解决的问题：**
- ✅ 解决LLM上下文窗口限制
- ✅ 实现跨会话的记忆保持
- ✅ 避免无关记忆干扰

### 3. 状态机驱动（State Machine）

**位置：** `AgentStateMachine` (state_machine.py:45-220)

**状态流转图：**
```
IDLE → INPUT_COLLECTING → DRAWING → INTERPRETING → REFLECTING → COMPLETED
       ↓                    ↓           ↓             ↓
       ERROR ←--------------┴-----------┴-------------┘
```

**设计亮点：**
- 明确的状态转换规则 `_ALLOWED_TRANSITIONS`
- 历史记录保留最近100条
- 状态持续时间统计
- RESET事件可从任何状态回到IDLE

**解决的问题：**
- ✅ 避免状态混乱和非法跳转
- ✅ 提供可观测的执行轨迹
- ✅ 支持错误恢复机制

### 4. 规划引擎（Planning Engine）

**计划类型：**

| 计划类型 | 步骤数 | 用途 |

| `create_interpretation_plan()` | 4步 | 初次解读 |

**执行计划结构：**

  - steps: [PlanStep, PlanStep, ...]

**设计亮点：**
- 计划可存储、可追踪、可回放
- 步骤级别的完成标记和结果记录
- 零影响设计，可选使用

**解决的问题：**
- ✅ 将复杂任务分解为可控步骤
- ✅ 支持执行计划的可视化和调试
- ✅ 便于中途恢复和重试

### 8. 三位一体的可观测性层（Observability）

**位置：** `AgentObservability` (observability.py:86-420)

**设计亮点：**

| 功能 | 实现方式 | 解决的问题 |
|------|---------|-----------|
| **结构化日志** | `log()` 方法，支持 trace_id 关联和丰富的 metadata | 日志散落在各处，难以关联 |
| **分布式追踪** | `TraceSpan` + `start_trace()`/`end_trace()`，支持父子跨度 | 无法追踪请求的完整链路和耗时 |
| **指标收集** | `MetricRecord` + `record_metric()`，内置7个核心计数器 | 缺乏运行数据，无法分析性能瓶颈 |
| **统计聚合** | `get_metrics_statistics()`/`get_trace_statistics()`，支持时间窗口过滤 | 原始数据太多，无法直观看到趋势 |

**核心设计：**
```python
# 零影响设计 - 可开关，失败不影响主流程
self.enabled = True  # 可以随时关闭
# 所有操作都是非阻塞的
# 数据先存内存，第三阶段再推送到数据库/监控系统
```

**内置7个关键计数器：**
```python
"total_requests"           # 总请求数
"interpretation_requests"  # 初次解读请求
"followup_requests"        # 追问请求
"successful_requests"      # 成功请求
"failed_requests"          # 失败请求
"guardrails_triggered"     # 安全护栏触发次数
"hallucinations_detected"  # 幻觉检测次数
```

### 10. 智能错误处理器（Error Handler）

**位置：** `ErrorHandler` (error_handler.py:61-323)

**四大核心能力：**

| 能力 | 实现方式 | 效果 |
|------|---------|------|
| **错误分类** | `categorize_error()` 分为4类 | 避免盲目重试 |
| **指数退避重试** | `calculate_retry_delay()` + 抖动 | 防止雪崩，平滑流量 |
| **多层降级策略** | `execute_with_fallback()` 主→注册→fallback→安全默认值 | 确保服务不中断 |
| **装饰器支持** | `@with_retry()` | 非侵入式使用 |

**错误分类：**
```python
TEMPORARY    # 临时错误（可重试）- 超时、5xx
PERMANENT    # 永久错误（不可重试）- 4xx
RECOVERABLE  # 可恢复错误（有降级方案）
UNKNOWN      # 未知错误
```

**指数退避算法：**
```python
delay = initial_delay * (backoff_factor ** retry_count)
delay = min(delay, max_delay)
# +20%抖动防止重试风暴
jitter_factor = 0.8 + random.random() * 0.4
delay *= jitter_factor
```

**降级链路：**
```
主函数 → 注册降级函数 → 提供的 fallback → 安全默认值
```

## 五、完整Harness架构设计亮点总结

| 层级 | 模块 | 设计亮点 | 解决的问题 |
|------|------|---------|-----------|
| **执行层** | ReAct Loop | 观察→思考→行动→循环，最多3步 | LLM一步到位的不准确性 |
| | Planning Engine | 多步执行计划，可追踪可回放 | 执行过程不透明 |
| | State Machine | 严格的状态转换规则 | 状态混乱 |
| **质量层** | Reflection Engine | 4维度检查 + LLM自动修正 | 输出质量不稳定 |
| | Guardrails | 强制格式+内容规范 | 违规内容输出 |
| | Hallucination Detector | 幻觉检测 | LLM胡说八道 |
| **记忆层** | Memory System | 工作/短期/长期三层，混合检索 | 上下文窗口限制 |
| **工具层** | Tool Orchestrator | 权限+参数验证+历史记录 | 工具调用混乱 |
| **可靠层** | Error Handler | 错误分类+指数退避+多层降级 | 服务易中断 |
| | Checkpoint Manager | 会话快照，可恢复 | 中断后重来 |
| **观测层** | Observability | 日志+追踪+指标三位一体 | 黑盒运行，无法调试 |
| **兼容层** | 双路径 + 旧接口 | 快速路径 + 完整路径可选 | 重构风险 |

## 六、核心设计哲学

1. **零影响重构** - 不破坏现有功能
2. **多路径可选** - 平衡性能和质量
3. **三位一体可观测** - 日志/追踪/指标完整
4. **多层防御** - 重试/降级/护栏/反思多重保障
5. **数据驱动改进** - 评测框架提供量化反馈
